# Project: Stock Movement Context Dashboard (DSO 576)

> This file is read automatically at the start of every Claude Code session. It is the standing context. Phase-specific instructions live in `phases/`. Running status lives in `PROGRESS.md`.

## 1. What this project is
A semester-long team project (teams of 5-6) for DSO 576, a Python course at USC Marshall. The course deliverable is a **live tool built around a business or policy decision**, plus a **written account of what the data can and cannot support**.

Our project: a **Stock Movement Context Dashboard**. When one of eight mega-cap stocks makes a large price move, the tool surfaces the surrounding context (filings and news from the same window) so a human analyst knows where to look first.

- It surfaces **context, not causation**. It must never claim that a news item or filing caused a price move.
- Output is a **shortlist for human follow-up**, not a verdict or a trading signal.

## 2. Who the tool is for
An **investor-relations analyst** at a company. They want to quickly see what was happening around a big move in a stock and decide what deserves a closer look. (This mirrors the course's Amazon category-manager example: the tool narrows the field, the human decides.)

## 3. Data

- Raw (never modify): `data/raw/{prices,news,filings}.parquet`. Rows: prices 2,656; news 3,888; filings 73.
- `data/raw/` is NOT in the repo (git-ignored). Teammates get the original download from Hugging Face `TheFinAI/Herculean`, pinned to commit `52d3ecb97e490a2392717935402cde283e8fa36e`. The README section "Getting the Data (pinned version)" has the download commands and SHA-256 hashes to check; save the files in `data/raw/`.
- Cleaned: `data/cleaned/{prices,news,filings}.parquet` (same row counts as raw), plus `data/cleaned/price_context.parquet` (2,656 rows: prices joined to news and filing links).
- Cleaning script: `src/dso576_python/cleaning.py` (run via `cleaning.main()`). The change log is `outputs/cleaning_changes.csv`.
- `data/cleaned/` is generated by `src/dso576_python/cleaning.py`. If the cleaning script or its logic changes, regenerate and commit the cleaned files in the same commit so the repo copy and the code never disagree.
- Note: the notebook `data_cleaning.ipynb` and the README use "Phase 1-4" for steps inside the cleaning notebook (inspect, clean, validate, outputs). These are NOT the course phases. Course Phase 1 = vision write-up; Phase 2 = this deliverable set.
- `sample/` holds a 50-row cleaned sample (CSV, text cut to 300 chars). Use it only for quick tests, never for analysis.
- Load with `pd.read_parquet("data/cleaned/<table>.parquet")`.
- STATUS: Shreya's cleaning (data/cleaned/) is the team's agreed canonical dataset. The team chose it as the single analysis-ready version. The cleaning deliverable (part of Phase 2) is done; remaining Phase 2 work is BUILD_SPEC.md and the backend analysis code.
